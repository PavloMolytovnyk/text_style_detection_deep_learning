# Архітектура нейромережевого сервісу

## Потік обробки

Streamlit отримує введений текст і викликає спільний Predictor локально або FastAPI через API_URL. Predictor завантажує ваги PyTorch, метадані й токенізатор з одного каталогу. Кожен текст проходить ту саму токенізацію, що й під час навчання. Спільний нейронний encoder створює представлення тексту, а дві окремі лінійні голови повертають по п'ять logits для стилю й тону.

CNN містить Embedding, три паралельні Conv1d з вікнами 3, 4, 5, ReLU, маскований max pooling, dropout і дві голови. Маскування виключає повністю доповнені позиції, щоб довжина інших текстів у batch не змінювала відповідь.

BiLSTM містить Embedding, двонапрямну LSTM, attention pooling, dropout і дві голови. Packed sequences прибирають вплив padding на рекурентні стани. Attention об'єднує вихідні стани в компактне представлення; голови використовують його разом із фінальними станами обох напрямів.

DistilBERT використовує попередньо навчений encoder `distilbert/distilbert-base-cased` і дві нові голови. Донавчання змінює і encoder, і голови. Це не виклик віддаленого LLM API. Після збереження ваг і токенізатора inference працює локально без завантаження базової моделі.

## Навчання й оцінювання

Функція втрат дорівнює сумі CrossEntropy для стилю та тону. Оптимізатор AdamW оновлює ваги за backpropagation. Gradient clipping обмежує норму градієнта. ReduceLROnPlateau зменшує швидкість навчання за валідаційною метрикою, early stopping зупиняє навчання без покращення. Checkpoint обирається за середнім macro F1 двох задач на validation.

Після вибору checkpoint одна скалярна температура для кожної задачі підлаштовує logits на validation. Калібрування не змінює argmax і не гарантує правильність окремого результату. Звіти містять accuracy, macro/weighted F1, precision/recall для класів, OVR ROC-AUC, ECE, negative log likelihood, матриці помилок і частку текстів, де обидві мітки правильні.

## Контракт API

- POST /predict: стиль, тон, оцінки всіх класів, попередження.
- POST /predict/style та /predict/tone: окремий результат зі збереженням початкових назв полів.
- POST /predict/batch: від 1 до 32 текстів.
- GET /health/live: процес працює.
- GET /health/ready: ваги успішно завантажені, інакше 503.
- GET /model/info: архітектура, класи, параметри й результати validation.
- GET /docs: інтерактивний Swagger.

Порожні тексти, сама пунктуація, завеликі запити та некоректні batch повертають 422. Максимум — 8000 символів на текст. Послідовність обмежується лімітом токенів конкретного checkpoint; відповідь явно повідомляє про обрізання. Недоступні ваги спричиняють 503, а не підміну прогнозу правилами чи випадковими мітками. Синхронні handlers FastAPI виконують CPU inference у thread pool.

## Відтворюваність

Артефакт містить tensor-only state_dict, JSON конфігурації та локальний токенізатор. Predictor перевіряє SHA-256 ваг і використовує `torch.load(weights_only=True)`. Шляхи обчислюються від кореня проєкту. CPU є стандартним режимом запуску, CUDA доступна для навчання. Точна бітова ідентичність між різними версіями PyTorch і пристроями не гарантується, тому версії та seed збережено в метаданих.
